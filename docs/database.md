# SQLite 数据库

## 数据库位置与生命周期

- 数据库文件名为 `db.sqlite3`，位于 `NGXOPS_HOME` 指定的数据目录；未设置时使用进程当前工作目录。
- 数据访问使用 SQLAlchemy 2.x 同步 Engine/Session。HTTP 请求使用独立 Session；后台线程必须创建自己的 Session，不跨线程共享。
- 应用启动不会创建表或自动升级结构。结构变更通过 `ngxops/database/migrations/` 中的有序迁移脚本维护。
- 数据库使用外键约束和 30 秒 SQLite 写锁等待。SQLite 同一时刻只允许一个写事务，事务应保持短小。

## 初始化与升级

首次安装时创建数据库并应用所有登记的迁移：

```bash
python -m ngxops --home "$NGXOPS_HOME" database init
```

已有安装升级前先停止 Web 服务并备份数据目录，然后应用尚未执行的迁移：

```bash
python -m ngxops --home "$NGXOPS_HOME" database upgrade
```

迁移由 `ngxops_schema_migrations` 记录版本，并通过 `BEGIN IMMEDIATE` 串行执行。含有业务表但没有有效迁移记录的数据库会被拒绝修改。不要使用 ORM 自动建表、手工删除版本记录或直接改写生产库。

表结构变化应提供向前迁移脚本，并明确对数据、索引、外键及备份恢复的影响。需要重建表时，在事务内检查外键一致性。

## 数据完整性约束

| 数据范围 | 主要约束 |
|---|---|
| 用户与权限 | 用户名、权限编码、角色名和用户组名唯一；关联关系有复合唯一约束或主键 |
| 登录与会话 | 会话句柄唯一；登录失败计数非负；会话内容不保存密码或 SSH 凭证明文 |
| SSH 凭证 | `(name, created_by)` 唯一；密码和私钥列仅存 Fernet 密文 |
| 节点与分组 | 节点 IP 唯一；节点组名称唯一；节点组成员关系唯一；软删除保留节点身份 |
| 配置与绑定 | `(config_id, node_id)` 唯一；绑定版本 `(binding_id, version)` 唯一 |
| 软件包 | 包身份受名称、版本和上传人组合约束 |
| 系统设置 | 设置 key 唯一；用户删除后修改人允许置空 |
| 操作审计 | 保留操作人名称快照；任务清理不级联删除审计记录 |

具体列类型、索引、外键及级联方式以当前 SQLAlchemy 模型和已登记迁移为准。添加约束前核对现存数据，不以应用层校验代替数据库约束。

## 任务和账户数据

- `ngxops_tasks` 保存操作类型、状态、进度、步骤、结果树、批次、目标摘要、触发人和执行时间。
- `ngxops_task_logs` 按任务追加记录，支持增量读取和节点筛选。任务结果树限制为 1 MiB，日志内容不得包含凭证明文、私钥、密钥或会话令牌。
- 应用启动时会将数据库中遗留的 `pending`/`running` 任务标为失败，不自动重跑远程操作。
- 登录失败状态、登录记录、RBAC 关联、系统设置和操作审计均由独立表保存；数据清理按设置的保留周期执行。

## 备份与恢复

备份前停止 Web 服务。数据库、`.secret_key`、`.fernet_key`、`nginx_packages/` 和需要保留的日志位于同一数据目录，应一起备份并限制备份访问权限。恢复时将这些文件放回相同的 `NGXOPS_HOME`，并确认服务账户具有目录读写权限。

`.fernet_key` 用于解密数据库内的 SSH 凭证密文；数据库与该密钥必须共同备份。`.secret_key` 用于签名会话和 CSRF Cookie；更换后现存 Cookie 将失效。
