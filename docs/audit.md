# 操作审计与登录日志

## 页面与权限

- `/audit/` 提供操作日志筛选、分页、任务跳转和模块快捷入口；关联任务的 `#任务ID` 在新标签页打开任务详情，任务创建日志将编号直接放入详情摘要；日期范围按北京时间解释。
- `/audit/logins/` 查询登录成功/失败记录、IP、浏览器标识和失败原因。
- 两页均要求 `audit.read`；超级管理员按全局权限规则通过。
- 操作日志按模块、结果、日期和逗号分隔关键词筛选；登录日志按结果、日期及用户名/IP 筛选。多关键词之间取交集，每个词匹配一行内任一目标字段。

## 写入规则

- 迁移 v13 新建 `ngxops_audit_logs`。操作人名称以快照保存，用户删除后保留记录并将用户 ID 置空；任务 ID 和批次号分别支持查询。
- SQLAlchemy Unit of Work 会将用户、凭证、节点/节点组、配置/绑定/版本、角色/用户组和 Nginx 源码/模块包的已提交新增、修改、删除写入同一事务。节点逻辑删除按删除记；节点资料修改使用“节点调整”动作，并记录节点标识和变更字段名；用户授权及成员批量操作另写摘要。
- `ngxops_tasks` 创建时按任务类型写操作摘要、最多五个目标节点及 IP、任务 ID 和批次号；任务 ID 在任务行 flush 后写入审计。凭证启用测试摘要不再重复输出内部操作类型和凭证 ID，而是显示“创建任务：#ID 目标…”；取消操作也在取消事务中写审计记录。
- 节点批量导入、节点导出、凭证明文导入和导出写一条批次摘要，避免逐行审计造成重复记录。凭证导出仅超级管理员可用，导入要求 `credentials.create`；导入先拒绝工作簿内及当前用户已有凭证重名，再全文件校验后统一提交。
- 凭证批量删除在审计抑制范围内完成 ORM flush，只写一条包含名称预览的汇总记录；审计详情展开显示在原单元格下方，固定列宽避免改变表格布局。
- 自动追踪只保存白名单对象标识和节点变更字段名，不记录任意备注内容或变更前后值。凭证日志不写密码或私钥，配置正文、会话密钥和异常原文不会复制进审计详情。凭证导出响应禁止缓存。
- 登录成功/失败记录复用 `ngxops_login_logs`，不在操作日志中复制密码或失败请求正文。
- 操作与登录日志统一使用 ASGI 提供的客户端地址，不直接信任请求头中的 `X-Forwarded-For`；反向代理部署应由 ASGI 服务器配置可信代理解析。

## 保留

操作日志和登录日志按 `system.retention_audit_log_days`、`system.retention_login_log_days` 分别保留；设置为 0 时关闭对应清理。系统每天最多启动一次后台清理，也可运行 `python -m ngxops.settings purge` 手动执行。日志列表不提供编辑、删除或导出。
